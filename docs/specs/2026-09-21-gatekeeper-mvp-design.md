# B站守门员（BiliGate）MVP 设计文档

日期：2026-09-21 ｜ 状态：M1 已构建（v0.1.0-mvp）｜ 项目：D:\hanpf\BiliGate

## 一句话

刷B站竖屏流（"看看"）时，无障碍服务读取当前视频标题/UP主 → Jev 三维判断是否营销号 → 提示 + 拟人上滑自动跳过；UP主累计 3 次被判自动拉黑，此后秒跳零成本。

## 背景与已验证前提

- Jev (TypeSafe AI) 判断营销号：桌面实测 6/6 命中（纯标题也 6/6），平均延迟 ~800ms，单次成本 ~$0.0002（详见 NormalDOC/_jev_mktg_judge.py）
- 无障碍方案：GKD（4万Star）验证的官方正门路线——读屏幕渲染文本 + 模拟手势，不root/不破解/不碰协议
- 法律边界（用户已确认）：**自用+免费开源分享**；不分发盈利、不碰广告、不逆向协议。李跳跳死因=规模化动了广告收入，本方案三条都不占

## M1 范围（本次已实现）

| 组件 | 文件 | 职责 |
|---|---|---|
| 屏幕监听层 | GateKeeperService.kt | B站包名过滤、600ms 去抖、BFS 收集节点文本、启发式识别标题/UP主、dump 校准模式 |
| 判断引擎层 | JevClient.kt | OkHttp 调 /v1/systemone，三维（性质 Choice/营销味 Score/标题党 Noul），IP直连可配，超时2-3s降级放行 |
| 信誉库 | UpBlacklist.kt | UP主 strike 计数（≥3拉黑）、白名单、SharedPreferences 存储 |
| 执行器 | Swiper.kt | 拟人上滑：随机延迟 + 双段弧线手势 |
| 设置页 | MainActivity.kt | 总开关/三档模式/IP直连/dump/战绩/清空 |

**跳过阈值**：性质∈{hard_ad, course_funnel, clickbait} 或 营销味≥2.5，且置信度≥0.8（宁漏勿误）

**三档模式**：0 提示1.2s后自动划（默认）/ 1 仅提示 / 2 直接划

## MVP 已知限制（真机校准项）

1. 标题/UP主提取是启发式（长文本非UI词=标题；短文本=UP主），B站"看看"流实际节点结构未经真机验证——**首次使用先开 Dump 模式**，把 logcat（tag=BiliGate）发给 AI 校准选择器
2. Jev key 内置（自用版）；将来开源分享前必须改为用户自填
3. 横屏连播/其他页面未适配（识别不出标题就静默，不影响）

## M2+ 路线图（用户已确认优先级）

1. **M2.1 协议直连"不感兴趣"**（最优先）：App 内扫码登录 → 标题反查视频ID（校验一致）→ 调 bilibili dislike 接口静默入库 + 划走。依据 bilibili-API-collect 社区文档；失败降级为仅划走
2. M2.2 横屏连播场景
3. M2.3 关注列表自动白名单
4. M2.4 评论信号二次复核（"恰饭""广告"密度）
5. M2.5 多平台（抖音/快手）
6. 远期：开源分享（key 自填 + 免责声明 + 用户自担风险）

## 风险与对策

| 风险 | 对策 |
|---|---|
| B站改版致节点失配 | 选择器集中在 Service 两函数，dump 模式快速校准 |
| 风控检测模拟手势 | 随机延迟+弧线+低频（每条视频一次） |
| Jev 超时/断网 | 降级放行，绝不卡观看 |
| 公司WiFi DNS 不解析 api.typesafe.ai | IP 直连开关（默认开，内置 OkHttp Dns 覆盖） |
| 误杀干货 | 置信度<0.8 放行；白名单；模式1可退化为纯提示 |
